## Immutable successor binding

Validation revision 3 explicitly supersedes revision 2. Its source binding includes
this contract, the unchanged revision-2 registration and sealed-manifest artifact.
The report schema advances to `phase55/validation-report-v2`. All original
definition/simulator digests, economic assumptions and disposition gates remain
unchanged. Freeze and commit `frozen-registration-v3.json` before replaying any
development observation under this successor. Its checkpoints use new registration,
evaluation and simulation identities; do not relabel old rows as verified new rows.

Report publication now binds the exact development bounds and terminal daily
checkpoint digest for every source instrument (including same-session confirmed
ORB comparators). Full-chain replay verifies decisions, accounting and continued
occupancy before either restart or publication. Verification caches contain only
computed proofs and compare the actual stored bytes again on every consumption;
a process restart reconstructs those proofs. Traversal has a fixed daily bound,
never follows caller-supplied predecessor links, and rejects missing/extra periods.
Pure arithmetic reducers and the English renderer do not authenticate input rows;
only catalog-backed publication produces the verified report binding. The internal
bulk publisher can preload one baseline population, but cannot receive user rows,
account counts, sessions, timeframes or alternative period labels.

`forecast_step` is a pure exposure-mapping capability, distinct from execution.
It invokes the unchanged EWMAC or breakout formula with the prior buffered value,
sizes from completed closes/sigma and conversion, schedules the next eligible D
opening (one further opening for the registered latency scenario), and charges
spread/commission/slippage only on the absolute unit change. Its state is separately
attributed by registration, strategy, instrument and scenario. It returns no fill,
P&L, or financed-return claim. Real daily batch observations remain unavailable
before price loading because this registration has no genuine financing source;
synthetic mapping tests cannot waive that gate. Admission of a future genuine
financing source would require a new immutable registration, not a flag here.
